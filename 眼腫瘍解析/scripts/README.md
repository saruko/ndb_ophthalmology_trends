# 眼腫瘍解析 追加解析スクリプト README

眼腫瘍手術トレンド解析（[../眼腫瘍手術トレンド_2014_2023.csv](../眼腫瘍手術トレンド_2014_2023.csv)）に対する
追加解析（年齢階級別層別化・rate換算・trend test）一式のスクリプトと、
そのデータ取得方法・解析方法をまとめる。

## 全体の流れ

```
1. extract_age_stratified.py   NDBオープンデータ(性年齢別)から眼腫瘍手術の年齢階級別件数を抽出・4群層別化
2. extract_age_population.py   総務省人口推計から4群別の全国人口を算出
3. rate_and_trend_analysis.py  上記2つを使い、人口10万対rate換算とPoisson回帰trend testを実施
```

依存ライブラリはプロジェクトルートの [requirements.txt](../../requirements.txt) と共通（pandas, numpy, statsmodels）。
`.xls`（2014・2016〜2018年の人口推計ファイル）の読み込みには `xlrd` が別途必要
（`pip install xlrd`。requirements.txt には未追加）。

---

## 1. extract_age_stratified.py

### 目的
既存の眼腫瘍手術トレンドCSVは全国合計値のみで年齢階級別データを含んでいなかったため、
NDBオープンデータの「性・年齢階級別」集計から年齢情報を補完する。

### データ取得方法
- **データソース**: 厚生労働省 NDBオープンデータ「K手術 款別性年齢別算定回数」
  （プレフィックス別ではなく、電算コード単位の個票データ）
- 第1回（2014年度）〜第10回（2023年度）の10年分をダウンロード済み
  （`data/raw/ndb_age_sex/ndb_shujutsu_agesex_{year}.xlsx`）。
- 各回のページURLとファイルURLの対応（探索時に確認したもの。将来再取得する際の参考）:

  | 年度 | NDBオープンデータ回次 | ファイルURL |
  |---|---|---|
  | 2014 | 第1回 | `https://www.mhlw.go.jp/file/06-Seisakujouhou-12400000-Hokenkyoku/0000140360.xlsx` |
  | 2015 | 第2回 | `https://www.mhlw.go.jp/file/06-Seisakujouhou-12400000-Hokenkyoku/0000177266.xlsx` |
  | 2016 | 第3回 | `https://www.mhlw.go.jp/content/12400000/000347727.xlsx` |
  | 2017 | 第4回 | `https://www.mhlw.go.jp/content/12400000/000711858.xlsx` |
  | 2018 | 第5回 | `https://www.mhlw.go.jp/content/12400000/000539726.xlsx` |
  | 2019 | 第6回 | `https://www.mhlw.go.jp/content/12400000/000821487.xlsx` |
  | 2020 | 第7回 | `https://www.mhlw.go.jp/content/12400000/001262185.xlsx` |
  | 2021 | 第8回 | `https://www.mhlw.go.jp/content/12400000/001122125.xlsx` |
  | 2022 | 第9回 | `https://www.mhlw.go.jp/content/12400000/001258346.xlsx` |
  | 2023 | 第10回 | `https://www.mhlw.go.jp/content/12400000/001493186.xlsx` |

  各回のトップページ（例: 第10回 `https://www.mhlw.go.jp/stf/seisakunitsuite/bunya/0000177221_00016.html`）
  内の「K手術」→「款別性年齢別算定回数」からもたどれる。ファイル名に反して「款別」だが、
  実体は電算コード単位の明細（既存の都道府県別ファイルと同じ粒度）である。

- **Excelの構造**（全年度共通、45列）:
  - シート: 2014年度のみ「全体」1枚、2015年度以降は「外来」「外来（加算）」「入院」「入院（加算）」
    （既存の都道府県別ファイルと同じ構成。加算シートは対象外）
  - 列0: 款、列1: 分類コード、列2: 分類名称、列3: 診療行為コード（電算コード）、
    列4: 診療行為名、列5: 点数、列6: 総計(算定回数)
  - 列7〜25: 男性の年齢階級別件数（0〜4歳, 5〜9歳, ..., 90歳以上の19区分, 5歳刻み）
  - 列26〜44: 女性の年齢階級別件数（同じ19区分）
  - `-` は10件未満の秘匿マスク。

### 抽出対象コード
既存の眼腫瘍手術トレンドCSVに含まれる16の電算コード
（K215-2, K216, K225, K225-2, K225-3, K225-4, K233, K234, K235, K236, K239, K241, K245, K265, K266×2）。
`TARGET_CODES` 辞書で定義。

### 層別化方法
5歳刻み19区分を以下の4群に集約（`bracket_to_group`関数）:
- 小児(0-14): 0〜4, 5〜9, 10〜14歳
- AYA(15-39): 15〜19 〜 35〜39歳
- 成人(40-64): 40〜44 〜 60〜64歳
- 高齢者(65+): 65〜69歳以上すべて

秘匿値（`-`）は**0として合算**する（プロジェクト本体`preprocess.py`のzero補完方針に合わせた）。

### 出力
- `眼腫瘍手術_年齢階級別_2014_2023.csv`: 5歳刻み・男女別の生データ
- `眼腫瘍手術_4群層別化_2014_2023.csv`: 4群集計
- `眼腫瘍手術_年齢別合計_整合性チェック用_2014_2023.csv`: 年齢を合計した値
  （**注意: この値は秘匿マスクの影響で真の全国合計より少なくなる。rate換算・trend testには使わないこと**、後述）

### 重要な発見（整合性チェック結果）
年齢・性別クロス集計から再合算した値を、既存の都道府県別集計由来の真の全国合計と比較したところ:
- 高頻度術式（K215-2, K225-2, K225-3, K234等）: 乖離は数%以内で妥当
- **低頻度術式（K233, K236, K245, K265, K266, K225-4）: セル単位の秘匿（10件未満マスク）により
  大半〜全部が0として欠測する**（例: K265/K266は全年度でほぼ0件しか復元できない）

この結果が、後述のtrend testでK265/K266を除外する根拠になっている。

## 2. extract_age_population.py

### 目的
年齢階級別の手術件数をrate（人口10万対）に換算するため、4群それぞれの全国人口を年次で用意する。

### データ取得方法
- **データソース**: 総務省統計局「人口推計」各年10月1日現在、全国：年齢（各歳）、男女別人口
  （第1表）
- ダウンロード先: `data/real_covariates/raw_download/age_pop/pop_by_age_{year}.xls(x)`
- URLパターン: `https://www.stat.go.jp/data/jinsui/{year}np/zuhyou/05k{連番}-1.xls(x)`
  - 連番は元号年（例: 2014年度→平成26年→`05k26-1.xls`）。2019年度（令和元年）は`05k01-1.xlsx`、
    2021年度以降は西暦そのまま（例: `05k2021-1.xlsx`）と、年度によって命名規則が異なる点に注意。
  - **2015年度・2020年度は国勢調査実施年のため「人口推計」の年次ページ自体が存在しない**
    （`stat.go.jp/data/jinsui/2015np/`, `2020np/` はいずれも404）。この2年は
    前後年（2014/2016, 2019/2021）の**線形補間**で代用した
    （`build_real_covariates.py`が医師数・施設数で採用済みの補間方針と同じ考え方）。

### Excelの構造
- シート「第1表」、12行目が「総数」行、13行目以降が年齢別データ。
- 表が横に2ブロックに分かれている: 列0-8が0〜49歳、列9-17が50〜100歳以上
  （紙面節約のためのレイアウト。列1・列10がそれぞれのブロックの「男女計」列）。
- 単位は千人。

### 層別化・出力
年齢を`age_to_group`関数で4群（extract_age_stratified.pyと同じ区分）に集約し、
`人口_4群層別化_2014_2023.csv`に出力（2015・2020年は`is_interpolated=True`のフラグ付き）。

### 検算
4群合計の総人口が総務省公表値（例: 2014年127,078千人、2023年124,354千人）と一致することを確認済み。

## 3. rate_and_trend_analysis.py

### 目的
チェックリストの残り3項目に対応する:
1. 人口10万対rateへの変換と、粗数トレンドとの方向一致確認
2. 虹彩・毛様体・脈絡膜腫瘍切除術（K265, K266）の「データ不足のため分析対象外」の明記
3. Poisson回帰によるtrend test（傾向性検定）でAPC・p値・95%信頼区間を算出

### 重要な設計判断: rate換算・trend testの母数には「真の全国合計」を使う
`extract_age_stratified.py`が出力する年齢別合計（`眼腫瘍手術_年齢別合計_整合性チェック用`）は、
前述の通り低頻度術式で秘匿による過小評価バイアスを含む。そのため rate換算・trend test には
**都道府県別集計由来の元の全国合計**（`../眼腫瘍手術トレンド_2014_2023.csv`の`Total_Count`、
`-`は0補完）を使用する。年齢階級別の内訳表示にのみ年齢・性別クロス集計を使う、という
使い分けをしている点が本スクリプトの肝。

### Poisson回帰の仕様
`count ~ year`（`year`は連続変数）に対し、`offset = log(全年齢人口)` を与えたPoisson GLM
（`statsmodels.api.GLM` + `families.Poisson()`）で傾向性検定を実施。
- APC (Annual Percent Change) = `(exp(β_year) - 1) × 100`
- 95%CIも同様に`exp`変換して算出
- p値は`year`の係数のWald検定によるp値

### 除外ルール
- **K265, K266**: 全年度でcountがほぼ0（秘匿による実質全欠測）のため、Poisson回帰が
  数値的に破綻する（尤度計算でNaNになる）。`EXCLUDED_CODES`で明示的に除外し、
  理由を`note`列に記載。
- **K225-4**: 2022年度新設コードのため観測年数が2年のみ。10年間のtrend testの対象としては
  不適切なため除外し、理由を`note`列に記載（改定前後の参考値算出は可能）。
- 上記以外で全年度count=0のコードがあった場合も同様にスキップするフォールバックあり
  （Poisson回帰の`deviance function returned a nan`エラー回避）。

### 出力
- `rate_per_100k_national_trend.csv`: 術式別・年次別の全年齢人口10万対rate
  （粗数トレンドとrateトレンドの方向一致は全16術式で確認済み。コンソール出力に一致判定あり）
- `poisson_trend_test_results.csv`: 術式別のAPC・95%CI・p値・除外理由

## つまずいた点・技術的メモ（再実行時の参考）

- **Windows環境のターミナル文字コード**: `python`実行時のprint出力がcp932ターミナルで
  文字化けする（ファイル自体はutf-8-sigで正しく保存されるので実害はない）。
- **`.xls`読み込みにはxlrdが必要**: `pandas.read_excel`は`.xlsx`はopenpyxl、`.xls`はxlrdを
  使うため、2014・2016〜2018年の人口推計ファイル（.xls形式）を読むには
  `pip install xlrd` が別途必要（本プロジェクトのrequirements.txtには含まれていない）。
- **`statsmodels`のconfint()の戻り値**: `sm.add_constant`にnumpy配列を渡すと
  `result.conf_int()`はDataFrameではなくnumpy配列を返すため、`.iloc[1]`ではなく`[1]`で
  アクセスする必要がある。
- **人口推計ページのURL規則が年度でバラバラ**: 元号年/西暦年が混在し、国勢調査年（2015, 2020）
  はページ自体が存在しない。今後別の年度を追加する場合は、まず
  `https://www.stat.go.jp/data/jinsui/{year}np/` にアクセスして実在を確認し、
  ファイル名は都度ページから確認するのが確実（命名規則を機械的に推測しない）。
- **`is_interpolated=True` が2015・2020になる理由（直感に反して見える点）**: 国勢調査年は
  国勢調査自体が最も正確な人口データだが、これは **総務省「人口推計」**（毎年10月1日現在の
  推計値を年次ファイルとして公表するシリーズ）とは別物。人口推計の個別年次ページ
  （`stat.go.jp/data/jinsui/2015np/` 等）は国勢調査年には作成されないため404になる。
  つまり2015・2020年の`is_interpolated=True`は「最も信頼できるデータを使わなかった」
  のではなく、「使いたいデータソース（人口推計年次ファイル）が存在しないため前後年から
  線形補間した」という意味。フラグの挙動は正しい。
